# 经验库（notes）

> 这里放**搭建自动化工作流时的经验**：选型、编排、交接物设计、降本、维护代价。
> 它们**不是案例**，不进 `cases/`，不进 `REPORT.md` 的任何统计，也不参与命中率。

---

## 为什么要有这一层

`cases/` 有一条硬门槛：**判据必须可证伪**——别人能照着 `falsifier` 在自己系统上跑一次，得到明确的红或绿。

很多真正有用的经验过不了这条门槛。比如「用 n8n 比自建调度省事」，它取决于团队、规模、预算，没有一条检查能判它红或绿。硬塞进 `cases/` 的后果是：分母被稀释，命中率变得没有意义——而**分母被稀释**恰恰是本仓库一直在防的事（见 `sf-0001`、`REPORT.md` 的口径说明）。

所以分两轨，互不污染：

| | `cases/` | `notes/` |
|---|---|---|
| 收什么 | 能推翻一条判据的反例 | 搭建过程中的取舍与代价 |
| 硬门槛 | 判据可证伪 | **必须写清代价**，否则是软文 |
| 进不进统计 | 进 | **不进** |
| 状态流转 | `draft` → `reviewed`（需他人复现） | 无状态，长期有效，可被后续案例推翻 |
| 署名 | `contributed_by` 字段 | 正文末尾标出处 |

**一条经验如果能写成可证伪的判据，它应该升级成案例，而不是留在这里。** 这是这一层存在的意义：它是案例的候选池，不是垃圾桶。

---

## 一条经验长什么样

见 [`TEMPLATE.md`](TEMPLATE.md)。五个字段：

- **场景**：什么流水线、什么规模、谁在跑。没有场景的经验无法复用。
- **做法**：具体怎么搭的，含选型与关键参数。写「用了 X」不够，要写「为什么不是 Y」。
- **代价**：维护成本、失败模式、什么时候会后悔。**这一格是门槛**——写不出代价的，是推广文案。
- **可复用结论**：一句话，能直接拿去问别人。
- **不构成案例的理由**：明确写出它为什么不可证伪。写不出来，说明它其实是案例。

## 命名与收录

- 文件名 `n-0001.md`，编号独立于 `cases/`，不占用 `sf-` 号段。
- 编号由维护者分配，投稿时不用自己取号。
- 投稿路径与案例相同：PR、issue、私信、EigenFlux 广播都行。
- 脱敏要求与案例一致：无绝对路径、内网地址、凭据、真实姓名、客户或学生信息。
