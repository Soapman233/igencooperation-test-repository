# 适用范围与边界

> 这份文档回答两个问题：**这套语料对你有没有用**，以及**你的系统算不算同类**。
> 它故意写得比 README 更宽——因为「静默失败」不是工程专属，它是任何「有绿灯、有账本」的流水线的通病。

---

## 一、适用条件：三条同时成立，就适用

不必是无人值守系统，不必是后端，不必是代码。只要下面三条同时成立：

1. **有一个判定点会给出「通过 / 成功 / 健康」**——退出码、状态字段、验收表、健康探针、审核勾选，都算。
2. **这个判定点的输入，来自被执行的一方本身**，或来自与被观察对象同源的路径。
3. **判定结果被写进账本，而账本又被用来做决定**——发版、交付、计费、结课、对外承诺。

满足 1 和 2 就已经可疑；加上 3，就一定会有人因此做错决定。

**判断你的系统适不适用，只需要问一句：这一轮如果根本没跑，账本上会多出一行什么？**
答不出来，就适用。

---

## 二、明确不适用（省得你白读）

- **纯计算、无外部副作用的模块。** 没有「没执行」与「执行了没结果」之分，就没有这条缝。
- **判据与被观察对象天然分离、且输入不共享的场合。** 例如独立第三方审计、双人复核且两人不读同一份数据。注意「独立」指的是输入独立，不是人不同——换个人读同一份写入方产出，只是换了个读法。
- **每一次都人工逐件核对产物的流程。** 这类流程确实不容易出本语料收录的形态，但代价是它不能规模化，而且人工核对本身会疲劳退化（见 `sf-0003` 那类「不会失败，而是永久阻塞」）。

---

## 三、跨域映射：同一条判据在不同领域的说法

这是本语料能跨出工程域的原因。**判据是抽象的，案例是具体的；收的是判据，不是案例。**

| 判据原型 | 教学资料流水线 | 内容生产流水线 | 数据管道 | Agent 工具链 | 自动化工作流搭建 |
|---|---|---|---|---|---|
| 报了成功但没执行 | 题库导出报成功，公式全变成图片 | 分镜渲染「完成」，音轨是空的 | 同步任务成功，游标原地未动 | 工具返回 ok，副作用没发生 | 节点显示 success，下游根本没收到数据 |
| 空与没跑同形 | 检索 0 条 ≠ 索引没建 | 无可用素材 ≠ 素材扫描失败 | 0 条新增 ≠ 这一轮没查 | 无回复 ≠ 消息没拉到 | 触发条件没满足被跳过，与「跑了但没命中」同色 |
| 自证型绿 | 用生成器自带的校验器验生成器 | 用同一个模型给自己的输出打分 | 用写入方自己的序列号验完整性 | 用执行方的日志证明执行方跑过 | 用工作流自己的执行日志证明这条工作流可靠 |
| 缺席被填成默认值 | 缺答案的题被填成「略」 | 缺镜头的分镜被填成占位图 | 缺字段被回填成 0 | 缺参数的调用被填成默认参数 | 必填参数缺失被填默认值，安静地跑出一批错数据 |
| 中间层没有回执 | 导出器报成功，打开才发现字体丢了 | 转码器报成功，播放器才发现丢帧 | 网关截断，前半截仍是合法 JSON | 安装器返回 0，运行时没加载 | 上游节点完成，下游没收到交接物，两边都认为对方在等 |

左列是判据，右边五列是同一判据在五个领域里的表现。**你在哪一列认出自己的系统，就投哪一列的案例。**

## 四、四问自检（三十秒，不用装任何东西）

1. 这个绿灯的读数，**是谁写的**？
2. 写它的人，和被执行的对象**是不是同一个**？
3. 如果这一轮**根本没跑**，账本上会多出一行什么？
4. 把这条判据**删掉**，结论会变吗？——不变，说明判据没承载信息。

四问里只要有一问答不上来，你的系统里就有这条缝，而且大概率不止一条。

## 五、当前覆盖的诚实边界

截至 2026-10-24，收录 8 条，领域分布：

| 领域 | 条数 | 案例 |
|---|---|---|
| `unattended-loop` | 2 | `sf-0001`、`sf-0004` |
| `filesystem-write` | 2 | `sf-0002`、`sf-0005` |
| `pagination` | 2 | `sf-0007`、`sf-0008` |
| `ci-pipeline` | 1 | `sf-0003` |
| `cli-arguments` | 1 | `sf-0006` |

**全部来自工程域。教学资料、内容生产、业务数据这三类，目前是零。**

这不是因为这些领域没有静默失败，而是因为**投稿的人都是工程师**。上面那张映射表是我们认为它们同构的理由，但**认为同构和收到案例是两件事**——所以这三类现在只能算「待验证的适用性」，不算「已证实的适用范围」。

如果你在做这三类流水线，你的一条案例比工程域的十条更有价值：它验证的是这套判据能不能跨域，而不只是又一个同域样本。

## 六、投稿时怎么标

- `domain` 用短横线小写标签，自拟即可（`document-pipeline`、`lesson-material`、`video-pipeline`、`data-sync`、`automation-workflow` 都行）。**不要求落在已有值里**——已有值只是建议，不是白名单。
- `reachability` 照实标：生产路径真能走到 = `production`；只在极端配置下能走到 = `edge`；理论存在没人见过 = `theoretical`。
- 不确定算不算同类？**先投**。判据可证伪就收，分类可以在评审时再对齐——把「不确定」写成「不投」，才是真的损失。

### 经验怎么办：走 `notes/`，不要硬塞进 `cases/`

搭建自动化工作流时的很多真东西过不了「可证伪」这道门——选型、维护代价、什么时候会后悔，都没有一条检查能判红绿。硬塞进 `cases/` 会稀释分母，而分母被稀释正是本仓库一直在防的事。

所以分两轨（详见 [`notes/README.md`](notes/README.md)）：

| | `cases/` | `notes/` |
|---|---|---|
| 收什么 | 能推翻一条判据的反例 | 搭建过程中的取舍与代价 |
| 硬门槛 | 判据可证伪 | 必须写清代价，否则是软文 |
| 进不进统计 | 进 | **不进** |

**一条经验如果能写成可证伪的判据，它应该升级成案例，而不是留在 `notes/`。** 那里是案例的候选池，不是垃圾桶。

## 七、这套判据不覆盖什么

- **它不告诉你系统会不会坏**，只告诉你「坏的时候账本会不会承认」。
- **它不替代测试**。测试回答「功能对不对」，本语料回答「判定本身可不可信」。
- **它不保证跨域等价**。第三节那张表是假设，需要案例来证实或推翻；发现某一行在某个领域不成立，那本身就是一条高价值投稿。
